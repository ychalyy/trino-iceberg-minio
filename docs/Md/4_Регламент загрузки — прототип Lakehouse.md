# РЕГЛАМЕНТ ЗАГРУЗКИ ДАННЫХ

**Первичная и повторная загрузка прототипа Lakehouse**

РЗ-ХД-LAKEHOUSE-01

Редакция 1.0 для рассмотрения

25 ноября 2026 г.

## 1 Назначение и область применения

Регламент описывает автоматизированную и пошаговую загрузку из tpch.tiny в Iceberg, формирование Data Vault 2.0, расчёт двух витрин, контроль и восстановление. Команды выполняются из корня репозитория в терминале хоста. Условия развёртывания и входа приведены в руководстве оператора, проверяемые сценарии — в документе «Качество данных и ПМИ».

Источник один, TPC-H SF 0.01. Реализованный инкремент меняет скидку одной отгруженной позиции. Процесс демонстрирует повторяемость и сохранение истории при этом изменении. Смена связей, удаление, запоздавшие события и параллельная загрузка с разных хостов не проверялись.

## 2 Термины и сокращения

Таблица 1 — Термины и сокращения

| Термин | Значение в прототипе |
| --- | --- |
| stage | SQL-представления типизированного источника, актуальных позиций и расчётных наборов. |
| raw | Восемь типизированных таблиц. Гранулярность: ключ источника и batch_seq. |
| vault | 6 Hubs, 6 Links и 8 Satellites. Хабы хранят бизнес-ключи, линки — связи, сателлиты — версии атрибутов. |
| mart | Два снимка агрегатов и два опубликованных представления. |
| ops | batches хранит статусы пакетов, dq_results — факты правил по попыткам. |
| hk и hashdiff | SHA-256 от упорядоченного JSON-массива. hk идентифицирует объект или родителя, hashdiff фиксирует состояние описательных атрибутов. |
| batch_id и batch_seq | Имя и порядковый номер пакета. Для публикации используются initial / 1 и delta / 2. |
| run_id | Идентификатор попытки. Фазы одной попытки связываются этим значением. |
| MERGE | Вставляет строки по отсутствующему ключу. Для версии также требуется отличие hashdiff от предшествующего. |
| Идемпотентность | Повтор операции сохраняет бизнес-данные и число версий. У новой попытки остаются собственные результаты DQ. |

Документы комплекта: ТЗ-ХД-LAKEHOUSE-01, ПЗ-ХД-LAKEHOUSE-01, МД-ХД-LAKEHOUSE-01, ПМИ-ХД-LAKEHOUSE-01 и РО-ХД-LAKEHOUSE-01.

## 3 Общая схема загрузки

Make вызывает scripts/lakehouse.py. Оркестратор выполняется на хосте, передаёт SQL по стандартному вводу в Trino CLI внутри контейнера и контролирует коды завершения. Пошаговые команды используют те же фазовые SQL-файлы.

Таблица 2 — Этапы загрузки и состояние данных

| Этап | Команда или SQL | Смысл результата |
| --- | --- | --- |
| Подготовка | make bootstrap<br>00-schema.sql, 10-source.sql, 40-marts.sql, 46-public-marts.sql | Создаёт схемы, таблицы и представления. При необходимости достраивает отсутствующие снимки ранее опубликованных пакетов. |
| Регистрация | register | Вставляет имя, номер, время и статус PENDING, если пакет ещё не зарегистрирован. |
| Входной DQ | input · 50-input-dq.sql | Сохраняет 33 результата. При FAIL обработка останавливается до Raw. |
| Raw | raw · 20-raw.sql | Добавляет строки выбранного пакета по ключу источника и batch_seq. |
| Data Vault 2.0 | vault · 30-vault.sql | Записывает Hubs, Links и отличающиеся версии Satellites в указанном порядке. |
| Снимки витрин | materialize · 45-mart-snapshots.sql | Фиксирует агрегаты по ключу группы и номеру пакета. |
| Модельный DQ | model · 60-model-dq.sql | Сохраняет 59 результатов по Raw, ключам, ссылкам, версиям и сверке снимков. |
| Публикация | publish | При результатах обеих фаз без FAIL обновляет статус пакета на COMPLETE. Обе витрины выбирают максимальный batch_seq со статусом COMPLETE. |

Редактируемая схема [«Последовательность загрузки Lakehouse»](../diagrams/load-sequence.drawio) входит в комплект. На ней отдельно показаны остановка после Raw, блокирующая ошибка и переход к публикации.

Операции Iceberg коммитятся по отдельным таблицам. Пока пакет остаётся PENDING, готовые строки в слоях могут быть видны через диагностический SQL, а опубликованные представления продолжают читать снимки предыдущего COMPLETE. При отсутствии такого пакета представления пусты.

## 4 Первичная загрузка

Для первичной загрузки нужен запущенный Compose-проект. Для сквозных испытаний используйте отдельный проект с чистыми томами. Команда load сама выполняет bootstrap. При пошаговой загрузке bootstrap необходимо вызвать явно перед регистрацией.

```bash
make up
make load BATCH=initial
make evidence
```

Initial загружает 86 805 строк в восемь таблиц Raw. Все 20 объектов Vault заполняются по исходным ключам и связям. После входного и модельного DQ обе витрины читают снимки пакета 1. Ожидаемые объёмы по таблицам приведены в модели данных и в ПМИ.

## 5 Повторная (инкрементальная) загрузка

Delta разрешена после COMPLETE для initial. Представление stage.lineitem выбирает первую по (orderkey, linenumber) отгруженную строку с положительной стоимостью и скидкой не выше 0,99. На подтверждённом наборе выбрана позиция (1, 1), скидка меняется с 0,04 до 0,05. Остальные входные таблицы для пакета 2 пусты.

```bash
make load BATCH=delta
make load BATCH=delta
make evidence
```

Повтор уже завершённого пакета выполняет обе фазы DQ с новым run_id. В основной фазе загрузки пропускаются запись Raw, Vault, снимков и публикация. Подготовка bootstrap может восстановить отсутствующие снимки уже опубликованных пакетов.

## 6 Обработка изменений без дублей

Таблица 3 — Правила записи слоёв

| Слой | Ключ операции | Обработка в демонстрации |
| --- | --- | --- |
| Raw | Ключ источника и batch_seq | Одна добавленная строка lineitem для delta. Исходная строка пакета 1 сохраняется. |
| Hubs, Links | hk | Состав бизнес-ключей и связей при изменении скидки сохраняется. |
| Satellites | (hk, batch_seq) | Для s_lineitem добавляется одна версия при отличии hashdiff. У остальных сателлитов версий пакета 2 нет. |
| Снимки mart | batch_seq и измерения группы | Оба снимка рассчитываются для delta. Продажи в одной группе меняются, отгрузки сохраняют значения. |

Хеш позиции Link учитывает orderkey, linenumber, partkey и suppkey. Скидка участвует в hashdiff сателлита. Сравнение выполняется с последней версией до обрабатываемого пакета. Версии пакета различаются при неизменном ключе позиции.

## 8 Идемпотентность и повторный запуск

Для воспроизведения остановки используйте проект, где initial завершён, а delta ещё не опубликована. Намеренная остановка возвращает код 1. При этом строки пакета 2 уже записаны в Raw, состояние остаётся PENDING, обе витрины показывают пакет 1.

```bash
python3 scripts/lakehouse.py load --batch delta --stop-after-raw
make load BATCH=delta
make evidence
```

Запускайте вторую строку после фиксации результата остановки. Повтор использует прежние batch_seq и loaded_at, а новый run_id отделяет проверки новой попытки. Повтор MERGE пропускает существующие ключи и добавляет только отсутствующие строки. Витрины переключаются после COMPLETE. Для восстановления используйте тот же вход. MERGE сохраняет существующие строки пакета. Изменённый вход после частичной записи проверяйте в чистом проекте.

Одна команда удерживает локальную блокировку по имени Compose-проекта. Для нескольких пошаговых команд важно сохранить порядок и проводить их последовательно одним оператором. Для ожидаемых ошибок каталога SQLITE_BUSY, SQLITE_LOCKED и неопределённого коммита используются до трёх запусков идемпотентного SQL с паузами 1 и 2 секунды.

Make demo включает обе загрузки, повторы, остановку после Raw и диагностический invalid. Запускайте его только в изолированном проекте до регистрации delta. Команда завершится успешно, когда отрицательный сценарий штатно заблокирован, а проверяемые значения сохранились.

## Приложение А. Пример MERGE для хаба

Фрагмент из 30-vault.sql показывает хеш-ключ клиента и вставку новой записи по отсутствующему hk. Параметр @batch_seq@ подставляется оркестратором перед передачей файла в Trino. Для размещения на странице выражение хеша перенесено на несколько строк.

```sql
MERGE INTO iceberg.vault.h_customer AS t
USING (
    SELECT DISTINCT
        to_hex(sha256(to_utf8(json_format(CAST(
            ARRAY['customer', CAST(custkey AS varchar)]
            AS JSON))))) AS hk,
        custkey, r.batch_seq, b.loaded_at, 'TPC-H' AS record_source
    FROM iceberg.raw.customer r
    JOIN iceberg.ops.batches b ON b.batch_seq = r.batch_seq
    WHERE r.batch_seq = @batch_seq@
) AS s
ON t.hk = s.hk
WHEN NOT MATCHED THEN INSERT
    (hk, custkey, batch_seq, loaded_at, record_source)
VALUES (s.hk, s.custkey, s.batch_seq, s.loaded_at, s.record_source);
```

Хеш вычисляется от массива с меткой customer и custkey. loaded_at читается из реестра пакетов. Для первичного источника record_source равен TPC-H. SELECT DISTINCT убирает повторы выбираемых строк на записи, входной DQ отдельно считает группы с дублированным ключом и блокирует ошибочный вход.

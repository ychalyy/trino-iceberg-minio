# Программа и методика испытаний Lakehouse

## Предусловия и порядок

Для испытаний нужны Docker Engine и Compose, локальный `.env`, Bash, Python 3.9+ и Make. Используйте отдельный Compose-проект с чистыми томами. Для проверки дашборда нужны профиль `bi` и браузер. Доступы, расположение файлов и точные действия приведены в [ручной инструкции](manual-verification.md).

Автоматический прогон `make demo` использует четыре положительные попытки с публикацией или повтором, остановку после Raw и отрицательный вход. Он сравнивает отсортированные значения обеих витрин на каждом переходе. Ручной прогон использует те же фазовые SQL-файлы. Идентификатор попытки сохраняется с результатом каждого правила.

## Сценарии по пунктам задания

| Проверка и требование | Предусловия и данные | Действия | Ожидаемый результат и свидетельство |
|---|---|---|---|
| **STAND-01-1**, запуск | Чистый проект, свободные порты, образы | `docker compose config --quiet`, `make up`, `docker compose ps` | Конфигурация принята, работают четыре сервиса. Сохранить вывод Compose |
| **STAND-01-2**, запись | Стенд работает | `bash scripts/stand-smoke.sh prepare` | `MERGE: 2 rows`, читаются `(1,trino)` и `(2,minio)`, бакет приватный, в нём Parquet и метаданные. Сохранить вывод и имена файлов |
| **STAND-01-3**, повтор | Контрольная таблица заполнена | Повторить smoke `prepare` | `MERGE: 0 rows` и те же строки. Сохранить вывод |
| **STAND-01-4**, пересоздание | Контрольные строки записаны | `docker compose down` без удаления томов, `make up`, smoke `verify` | Те же две строки и объекты. Сохранить вывод |
| **SRC-02-1**, источник | `tpch.tiny` и `initial` | Сравнить восемь результатов `RAW_COUNT` и блок Raw запроса `90-evidence.sql` | Каждый объём совпадает с TPC-H. Записать восемь объёмов |
| **SRC-02-2**, ключи и типы | `initial` | Проверить `KEY_NULL`, `KEY_DUPLICATE` и `INPUT_FK`. Открыть ERD и сверить типы с [моделью](data-model.md) | Уникальные ключи, ссылки находятся, цены и ставки типизированы |
| **DV-03-1**, структура | `initial` прошёл | Просмотреть `SHOW TABLES FROM iceberg.vault`, ERD и `VAULT_FK`, `VAULT_KEY_DUPLICATE` | Шесть Hubs, шесть Links, восемь Satellites. Ноль дублей и нарушений связей |
| **DV-03-2**, версия | `initial` и `delta` опубликованы | Выполнить `90-evidence.sql` | Для позиции `1/1` видны скидки `0.04` и `0.05` и пакеты 1 и 2 |
| **MART-04-1**, сверка групп | Оба кандидата рассчитаны | Проверить по два результата `MART_RECONCILE` на пакет | Симметрическая разница между Vault и Raw по группам равна нулю |
| **MART-04-2**, бизнес-эффект | В дельте одна скидка | Сверить фактическую и ожидаемую разницу из `90-evidence.sql` и группы отгрузок | Разница продаж `−247.1035` в затронутой группе, ноль изменившихся групп отгрузок |
| **LOAD-05-1**, повторы | Чистый проект с источником | `initial → повтор initial → delta → повтор delta` | Пакеты публикуются по одному разу. Повторы сохраняют витрины и число версий |
| **LOAD-05-2**, восстановление | Выполнен `initial` | Запустить `delta --stop-after-raw`, сверить витрины, повторить `delta` | После остановки бизнес-данные прежние. После повтора дельта опубликована, в сателлите две версии позиции |
| **DQ-06-1**, положительный вход | Выполнен положительный пакет | `make dq` и проверка протокола | Полный прогон сохраняет 33 входные и 59 модельных проверки со статусом PASS |
| **DQ-06-2**, ошибочный вход | Дельта опубликована. `invalid` содержит скидку 1.25 | Запустить `python3 scripts/lakehouse.py input --batch invalid --run-id manual-invalid`, запросить DQ и витрины | Код 1. `DISCOUNT_RANGE` показывает 0 / 1 / FAIL. Витрины совпадают с предыдущим снимком |
| **BI-07-1**, импорт | Чистые метаданные Superset, данные Trino загружены | Запустить профиль `bi`, импортировать ZIP, открыть вкладки | Один дашборд, шесть визуализаций и две вкладки |
| **BI-07-2**, DQ и фильтры | Есть результаты успешного и ошибочного запуска | Выбрать FAIL, правило и запуск. Сверить с SQL | Видно отклонение `DISCOUNT_RANGE` с фактом 1. Успешный запуск показывает PASS |
| **BI-07-3**, бизнес-метрики и фильтры | Обе витрины опубликованы | Выбрать период, регион и способ доставки. Сверить таблицы и графики с SQL | Метрики совпадают. Фильтры DQ бизнес-вкладку не меняют. Доля считается через суммы |

[Первичный протокол стенда](stand-acceptance.md) содержит результаты первого этапа. Результаты сквозной приёмки приведены в [отдельном протоколе](acceptance-results.md).
